# smart-reload の実装メモ

「操作中は見送る・変化したときだけ更新する・スクロールと入力を戻す」自動リロード拡張。
Easy Auto Refresh (ksoft) の構成を読んだうえで、**タイマーの置き場所を変えて**作り直したもの。
機能一覧と使い方は README.md にある。ここは「なぜそうなっているか」だけ。

## ファイル構成

```
manifest.json          MV3。permissions は storage / tabs / scripting / notifications
src/shared.js          定数・プロファイル正規化・パターンマッチ・ハッシュ。3箇所から読まれる
src/content.js         本体。タイマー・スキップ判定・復元・変化検知が全部ここ
src/background.js      service worker。アイコン/バッジ/通知/ショートカット/初回注入だけ
src/popup.*            ツールバーのポップアップ
src/options.*          既定の設定とルール一覧
icons/icon.svg         アイコンのソース1枚。PNG は icons/build.sh で書き出す
test/e2e.js            リロード動作の E2E。test/fixture.js がテスト用サーバ
test/options.js        設定画面の E2E
test/popup.js          ポップアップ(主に「ルールとして保存」)の E2E
```

## いちばん大きい設計判断: タイマーは content script が持つ

本家 Easy Auto Refresh は service worker 側で `setInterval` を回し、MV3 で 30 秒で
止められるのを **タブに `chrome.runtime.connect({name:"keepAlive"})` を注入して 295 秒ごとに
張り直す**ことで延命している。この拡張はそれをやらない。

- スキップ判定 (フォーカス・選択・メディア)、スクロール/フォームの復元、変化検知の
  `fetch` は、どれもページの中の情報が要る。タイマーも同じ場所にある方が素直。
- service worker が寝ていてもリロードが止まらない。background は状態を持たない。
- 60 秒未満は `setInterval`・以上は `chrome.alarms` という本家の分岐も要らなくなった。

### バックグラウンドタブのタイマー

引き換えに、ページのタイマーはタブが隠れていると絞られる (5 分以上隠れると 1 分粒度)。
ただし**リロードするたびに新しいドキュメントになって猶予がリセットされる**ので、
5 分未満の間隔なら実質影響を受けない。5 分以上の間隔、または変化検知で
「変化なし」が続いてリロードが起きない状態だと、最大 1 分ほど遅れて発火する。
発火時刻は `Date.now()` で見ているので、遅れても間隔がずれ込んでいくことはない。

これが許容できなくなったら、`chrome.alarms` を service worker 側の保険として足す形にする
(content script のタイマーは残したまま、遅れを検知したら alarm で起こす)。

## 状態の持ち方

| 置き場所 | 何を置くか | 消えるタイミング |
| --- | --- | --- |
| `chrome.storage.local` | 既定の設定 (`defaults`)、ルール (`rules`) | 明示的に消すまで |
| ページの `sessionStorage` | 実行中セッション、リロード直前の復元データ | タブを閉じたら |
| content script のメモリ | 残り時間・見送り回数・変化検知の基準ハッシュ | リロードのたび |

**タブごとの実行状態を storage に持たない**のが本家との違い。`sessionStorage` に置くと
タブ固有・タブを閉じれば自動で消える・リロードを跨げる、が全部ただで手に入る。
tabId を鍵にした表を service worker で管理する必要がない。

セッションは `source` で 2 種類に分かれる。

- `manual` … ポップアップで ON にしたもの。`sessionStorage` から引き継ぐ
- `rule` … ルールで自動 ON になったもの。**引き継がず毎回ルールから引き直す**
  (ルールを編集したら開きっぱなしのタブにも効くように)

同じオリジンの別ページに移動したときは引き継がない。`sessionStorage` はオリジン単位なので
URL を突き合わせて判断している。

サイト別の設定は持たせていない。本家はドメイン名を storage のキーにして設定を丸ごと
保存していたが、ルール機能があれば足りるので一本化した。

## バッジとアイコンの表示

- アイコンは ON = 青 / OFF = グレーの2状態だけ。**アイコン自体はアニメーションしない**。
- バッジは ON のあいだ出しっぱなし。テキストは `SR.BADGE_ON`(**空白1文字**)で、
  文字を見せずに色の付いた丸だけを出している。
- 動作中は **濃い色 (`SR.BADGE_COLOR`) と淡い色 (`SR.BADGE_PULSE_COLOR`) を1秒ごとに
  入れ替えて明滅**させる。
- 残り `COUNTDOWN_FROM` (10) 秒を切るとテキストが秒数になり、**明滅は止まる**
  (数字の下で色が動くと読みにくいため)。
- アイコンもバッジも `tabId` 単位なので、**表示されるのはアクティブタブの分だけ**。

### 空バッジは描画されない

`setBadgeText` に**空文字を渡すとバッジ自体が消える**ので、「文字なしで色だけ」はできない。
色を見せたいなら何か文字が要る。そこで空白1文字にしてある。

空白が本当に「文字の見えない色付きの丸」として描画されるかは**実機で未確認**。
Playwright はページの中しか撮れず、ツールバーは撮れない。`--load-extension` の拡張は
Preferences に登録されないのでピン留めの設定を書き込む手も使えず、`screencapture` でも
ウィンドウを捉えられなかった。丸が出ない環境に当たったら `SR.BADGE_ON` を `'●'` に
変えれば直る — **そのために1箇所の定数に寄せてある**。

### 明滅を止める3つの条件

`badgeColor(remain)` で、次のときは色を固定する。

1. **見送り中** … グレーで固定。待っていることを色で示す
2. **カウントダウン中** (`remain <= COUNTDOWN_FROM`) … 数字を読ませたいので濃い色で固定
3. **裏に回っているとき** (`document.visibilityState !== 'visible'`) … 下記

3 の理由は2つ。

1. 裏のタブのバッジはそもそも描画されないので、動かしても誰も見ない。
2. **1秒ごとのメッセージは service worker のアイドルタイマー(30秒)を延々とリセットする。**
   絞らないと、裏で自動リロードしているタブがあるだけで常時起動になる。

コストの計算は素朴な直感とずれるので、いじる前にこの式で確かめること。
明滅を止めている間にイベントが飛ぶのは「リロード直後の状態通知(t=0)」と
「残り `COUNTDOWN_FROM` 秒の毎秒更新」だけなので、間隔 I 秒に対して
**眠れるのは `I - (COUNTDOWN_FROM + 30)` 秒**。40秒以下の間隔では絞っても
どのみち常時起動で、差が出るのは分単位の間隔のときだけ。

### 採らなかった案

- **アイコン自体を脈打たせる** … バッジで足りるうえ、`setIcon` を毎秒呼ぶことになる。
- **常時カウントダウン表示** … 毎秒更新のコストは色の明滅と同じ。情報量では勝るので、
  明滅より数字が良いとなったらこちらに切り替えてよい(コストは変わらない)。
- **見送り中に専用の記号(`‖`)を出す** … 色で区別できるので文字は増やさない。

### テストの都合

**Playwright は裏のタブも `visible` のままにする**ので、タブを切り替えても
可視状態の分岐を再現できない(`vis-probe` で確認済み)。`test/e2e.js` では
service worker から `chrome.scripting.executeScript` で**content script と同じ
ISOLATED world** にコードを流し込み、`document.visibilityState` を差し替えて
実際のコードパスを通している。

バッジの実際の値は `chrome.action.getBadgeText` / `getBadgeBackgroundColor` を
service worker 側から読んで確かめられる(描画そのものは確認できない)。

## ルールの照合と「ルールとして保存」

**ルールは上から順に照合し、最初に当たった有効な1件だけを使う** (`SR.findRule`)。
2件目以降は見ない。この性質から、素朴に書くと壊れる場所が2つある。

### パターンの既定はフルパス

「ルールとして保存」が作るパターンは `origin + pathname + search`。
ハッシュは落とす (クライアント側だけの値で、取り直す HTML には影響しないため)。
クエリは残す (別のページとして扱いたいため)。
`://` を含むので `SR.matchesPattern` では完全一致になる。

最初はホスト全体 (`origin + '/*'`) を既定にしていたが、**同じサイトの別ページで保存すると
先に保存したページの設定が警告なく上書きされていた**。パターン文字列が同じになるため。
ページごとに別設定を持てないのも不便なので、フルパス既定に変えた。
サイト全体にしたいときはポップアップの「このサイト全体にする」で広げる。

### 既存ルールの探し方と差し込み位置

- **更新するかどうかは、パターン文字列の完全一致で判断する。** これは意図どおり
  「同じルールをもう一度保存した」ケースだけを拾う。
- **新しいルールを足すときは、同じ URL に当たる既存ルールの直前へ差し込む**
  (`rules.splice(at, 0, ...)`)。末尾に足すと、先に当たる広いルールに食われて
  **一度も発火しないルール**ができる。「追加しました」と出るのに何も起きない、という
  一番たちの悪い壊れ方をする。
- ポップアップの初期値に「今当たっているルールのパターン」を入れてはいけない。
  `https://example.com/*` が1つあるだけで「このページだけ別設定」ができなくなる。
  既存ルールとの関係はヒント行で知らせるに留める。

### ルールの名前 (`note`)

`note` は単なるメモではなく、**ポップアップのヘッダーに出る表示名**。空ならパターンを出す。
「ルールとして保存」では `note` を**空のまま**にしている — フルパス既定だと同じホストの
ルールが複数並ぶので、ホスト名を既定にすると全部同じ表示名になって見分けがつかなくなる。

ヘッダーに出すのはセッションが `rule` 由来のときだけ。手動 ON のときにルール名を出すと、
実際にはそのルールが効いていないのに効いているように見えてしまう。
そのときはホスト名を控えめに出す (`.heading.plain`)。

### 設定画面の並べ替え (ドラッグ&ドロップ)

`yt-quick-filter` の実装に合わせてある。要点は3つ。

- **`draggable` はハンドル (`⠿`) だけに付ける。** 行全体を draggable にすると、
  入力欄のテキスト選択やトグルの操作が効かなくなる。
- **リスナーは行ではなくリスト (`#rules`) 側に置く。** `renderRules()` が
  `replaceChildren` で行を作り直しても生き残る。
- **ドラッグ後に `renderRules()` を呼ばない。** DOM は既に正しい順に並んでいるし、
  描き直すと開いていた `<details>` が閉じる。DOM の `data-id` の並びから
  `rules` を組み直して保存するだけにする (`persistOrder()`)。

この「再描画しない」の副作用として、**描画時に閉じ込めた添字が当てにならなくなる**。
削除ハンドラを `remove(index)` のままにしていたら、並べ替えたあとに × を押すと
別のルールが消えた。`remove(rule.id)` に変えてある。行に紐づく操作は必ず id で引くこと。

Playwright の `page.dragAndDrop()` は実マウス操作を送るので、Chromium が
ネイティブの HTML5 ドラッグを起こしてくれる。`test/options.js` がこれで検証している。

これらは `test/popup.js` が回帰テストとして押さえている。ポップアップは Playwright から
直接開けないので、`popup.html` を普通のタブで開き `chrome.tabs` だけスタブしている。

## 各機能の注意点

### スキップ判定

- **入力中の判定は「フォーカスがある」だけでは駄目**。空の検索ボックスにカーソルが
  残っているだけで永久に止まる。値が空でないことを条件にしている。空欄に打ち始めた
  直後は「直前に操作した」が拾う。
- **ミュートされたメディアは再生中に数えない**。ニュースサイトの記事上部で自動再生される
  装飾用の動画まで拾うと、ほぼ全部のサイトでリロードが止まらなくなる。
- 同一オリジンの iframe は `contentDocument` を辿って見ている (`eachDocument()`)。
  クロスオリジンは覗けないので埋め込み動画は検知できない。
- スクロールは `scroll` ではなく `wheel` / `touchstart` で拾う。自前の復元でも `scroll` が
  発火してしまい、自分の操作を「ユーザーの操作」と誤認するため。

### 復元

- **パスワード欄は絶対に保存しない** (`UNSAVED_TYPES`)。file / hidden も同様。
- React などの制御コンポーネントは `value` を instance 側で上書きしているので、
  `el.value = x` では変更に気づかない。`HTMLInputElement.prototype` の setter を
  `call` してから `input` / `change` を投げている (`setFieldValue()`)。
- **スクロール復元のリトライは「誰かが動かしたら降りる」こと**。遅延読み込み対策で
  100/300/700/1500ms に再試行するが、素朴に書くとリロード直後 1.5 秒間は
  スクロールしても引き戻される。自分が最後に置いた位置から動いていたら、
  他の誰かが動かしたとみなして再試行をやめる (E2E で実際に踏んだ)。

### 同じタブの中での移動 (SPA 遷移)

`tick()` は発火判定より先に `navigated()` を見る。`SR.pageKey(location.href)` が
セッション開始時と変わっていたら、そのセッションを降ろす。

**これが無いと、移った先で必ず 1 回リロードが走る。** 文書が作り直されないので
content script もタイマーも生き残り、次の発火で新しいページを `location.reload()`
してしまう。そのリロードで初めて `init()` が「保存したセッションの URL と違う」と
気づいて止まる、という 1 回だけ壊れる挙動になる。YouTube の配信待機ページ
(`/@channel/live` → `/watch?v=...`) で踏む。**Easy Auto Refresh も同じ挙動**なので、
ここは差分になっている。

- **検知は tick の中でのポーリング。**リロードが起きうるのも tick なので、
  毎秒の突き合わせで必ず先回りできる。イベントで拾う必要がない。
- **`popstate` では拾えない。**ページ自身の `pushState` / `replaceState` では発火しない。
  ISOLATED world からは `history` にパッチも当てられない (MAIN world の別グローバル)。
  Navigation API (`navigation`) が ISOLATED world に生えている保証も無いので使わない。
  `chrome.webNavigation.onHistoryStateUpdated` なら確実だが、permission が 1 つ増える
  わりに 1 秒のポーリングと差がない。
- **比べるのはハッシュを落とした URL** (`SR.pageKey`)。ページ内リンクを踏んだだけで
  止まると使いものにならない。ハッシュルーティングの SPA では検知できないが、
  そもそも変化検知も効かない種類のページなので許容する。
- 変化検知の `fetch` を待っている間にも移りうるので、`fire()` の `doReload()` 直前でも
  もう一度見ている。
- 降ろし方はセッションの出どころで変える。`manual` はそのページへの指示なので止めるだけ。
  `rule` は移った先の URL で `applyRules()` を引き直す — **広いルール
  (`https://www.youtube.com/*`) を書いていると移った先でも当たって動き続ける**ので、
  「配信が始まったら止まってほしい」用途ではフルパスのルールにすること。

### 変化検知

- 比較するのは **`fetch` してきた HTML 同士**。画面に出ている DOM はページの JS に
  書き換えられていて、取ってきた HTML とは別物なので混ぜてはいけない。
- そのため **SPA では効かない**。README にも書いてある。
- ハッシュは `crypto.subtle` ではなく自前の FNV-1a。`crypto.subtle` は secure context が
  要るので `http://` のページでは `undefined` になる。
- `fetch` に失敗したら「変化した」扱いにしてリロードする (fail-open)。
  止まってしまうより、ふつうの自動リロードに落ちる方がまし。
- 「変化なし」で見送ったときの次回待ち時間は **`retryDelay` ではなく `interval`**。
  ここを他のスキップ理由と同じにすると数秒おきに `fetch` し続けることになる。

## ハマった点

- **`const SR = {}` は content script では危ない**。ポップアップから
  `scripting.executeScript` で流し込み直すと二度目の評価で
  `Identifier 'SR' has already been declared` になり、注入ごと失敗する。
  `var SR = globalThis.SR || (globalThis.SR = {})` にしてある。
- **`chrome.action.setIcon` の相対パスの解決先が紛らわしい**。`src/` 配下の service worker
  から呼ぶので、`chrome.runtime.getURL()` で絶対 URL にしてから渡している。
- **MAIN world で `Object.defineProperty(video, 'paused', ...)` してもテストにならない**。
  content script は ISOLATED world にいて、そこからは元の値が見える。E2E では
  実際に音が鳴る `<audio>` を置き、Brave を `--autoplay-policy=no-user-gesture-required`
  で起動して試している。
- **ブラウザ自身のスクロール復元と区別がつかない**。E2E では
  `history.scrollRestoration = 'manual'` にしてから測り、拡張の復元が効いていることを確かめている。

## テストの回し方

`~/projects` 共通の方針どおり、Playwright で **Brave Browser Nightly** を駆動する
(リリース版 Chrome は `--load-extension` を黙って無視する)。

```sh
PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm install
npm test
```

`test/fixture.js` が :8765 で小さなサーバを立てる。`/set-marker?v=...` を叩くと
返す HTML が変わるので、変化検知はこれで試している。

content script の操作は **service worker 越し**に行う。Playwright から
`context.serviceWorkers()[0].evaluate()` すると chrome API が使えるので、
そこから `chrome.tabs.sendMessage(tabId, {type:'getStatus'})` などを投げる。
ポップアップの UI は直接クリックできないので、レイアウト確認は
`chrome-extension://<id>/src/popup.html` を普通のタブで開き、`addInitScript` で
`chrome.tabs` をスタブして撮っている (scratchpad の `shots.js` がその例)。

## アイコン

ワークスペース共通ルール (背景なし・線画・`#1A73E8`・`viewBox="0 0 24 24"`) に従っているが、
**矢じりだけ塗り (`fill`) にしている**のが唯一の逸脱。線だけの V 字の矢じりは 16px で
完全に潰れて「C」にしか見えず、時計回りの矢印だと読めなかった。円弧は `fill="none"` の
ストロークのまま。OFF 状態はグレー (`#9AA0A6`) 版で、`icons/build.sh` が
`icon.svg` から色を差し替えて両方を書き出す (ソースの SVG は 1 枚だけ)。

矢じりを描くときは、**円弧の端の丸キャップが三角からはみ出さないよう**に弧の始点を
三角の内側に少し食い込ませること。はみ出すと 128px で小さな突起になって汚い。

## バージョニング

`~/projects` 共通の方針 (Keep a Changelog + SemVer、タグは `v` なしの数字のみ、注釈付きタグ)。
ユーザー向けの変更を入れたら `CHANGELOG.md` の `[Unreleased]` に 1 行足す。
リリース時に `manifest.json` の `version` と揃える。
